# 用户剧本：下一阶段设计边界

当前 `GameCatalog` 从部署者维护的 JSON 文件加载官方剧本；玩家不能通过网页上传或编辑剧本。上线前的私有剧本仍通过 `catalog.json` 发布，不依赖用户上传接口。

下一阶段把“创作草稿”和“可游玩版本”分开：

1. 登录用户创建私有草稿，填写标题、简介、角色、公开世界设定、初始状态和剧情节点。表单逐步保存；草稿不会出现在玩家大厅。
2. 上传文件作为草稿导入途径，只接收限定大小的 JSON/ZIP。服务端限制压缩包展开总量和文件数量，拒绝绝对路径、`..`、符号链接及意外文件类型，再按现有 `ScenarioPackage`/`CampaignProgram` 规则校验并显示具体错误。
3. 发布时生成不可变版本和内容指纹。玩家存档固定到该版本；作者修改草稿后必须发布新版本，不能原地改写旧存档所依赖的内容。
4. 目录读取层合并官方剧本与已发布的用户剧本，按作者、可见范围和下架状态过滤。游玩入口只接收服务端授予的剧本 ID，不能把客户端路径交给文件系统。
5. 在允许公开发布前，增加作者配额、上传内容审核和举报/下架流程。发布权限可先限定内测作者。

这项功能需要新的持久化表、文件存储、校验服务、创作界面与权限规则；它不应修改当前静态剧本包格式，也不应把用户上传目录直接挂进公开的官方目录。
