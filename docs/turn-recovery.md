# 回合结算恢复边界

本轮为 T04 的第一部分，尚未实现完整的逐次模型调用 journal。新增迁移 `0012_turn_settlements` 只创建 `turn_settlement_intents`，不修改历史事件或历史账单。生产数据库未在本轮迁移。

## 已可恢复的故障

完整回合生成结束后，服务在扣费前保存不可变的结算快照：`game_id`、`request_id`、输入哈希、格式版本、最终正文与状态、实际 Token 用量、完整价格配置及定价版本。重试先读取成功回执，再读取结算快照。

如果结算连接失败或进程在快照保存后退出，使用相同请求 ID 和输入重试会直接按快照结算，不重新调用故事模型。钱包扣款、流水和最终回执仍在同一事务内保存。结算成功但响应丢失时，重试读取已有回执，不再次扣款。

价格快照保留 Decimal 字符串，重试不会采用重启后变更的价格。即使当前配置关闭新回合计费，已有付费回合仍按其保存的价格和用量结算。余额不足时沿用原有“扣费不超过余额”规则，同时记录完整供应商用量成本。

## 仍需人工恢复的故障

已经提交 `input/query/action/continue/choice/advance/completed` 事件，但没有成功回执或结算快照的非审核预览请求，返回 `TURN_RECOVERY_REQUIRED`；HTTP 状态 409，SSE 返回错误事件，`commit_state=unknown`、`retryable=false`。它可能是旧版本遗留请求，也可能在本轮代码的世界提交与快照保存之间中断。

客户端保留原请求，不允许直接清空后发送另一个行动。刷新后尚未接入持久化状态查询，可能再次出现原请求重试入口；服务器仍会拒绝没有计量依据的结算。该错误不表示自动恢复已经完成。

处理时先备份对应存档的世界事件、账单、回执及已有快照，核对原请求 ID 和模型调用证据。不要删除世界事件来“解除卡住”，不要伪造零用量、补造历史扣费或手工标记成功。本轮没有提供自动修复这些请求的命令；完整结果与用量 journal、恢复状态接口及管理员恢复流程属于后续 T04。

审核预览沿用免费模式；已有成功回执继续正常读取。关闭计费配置不能作为绕过旧请求计量缺失的手段。

## 发布前仍需验证

- 迁移在隔离 PostgreSQL 上的升级与兼容性；目前只有 SQLite 实测。
- 完整模型调用结果在世界提交前持久化，覆盖更早的失败阶段及失败尝试成本追踪。
- 多进程或多实例执行的共同锁及并发恢复；目前仍按单 API worker 部署约束执行。
- 浏览器完整恢复流程、状态查询和管理端异常处置。

结算快照保留故事正文并与成功回执存在内容重复。它属于存档数据，应沿用相同访问控制、备份和保留策略；本轮没有启动自动清理。

## 已弃用的多 Agent 存档

Harness 0.2 与平台不再执行 `npc_reply` 待办。此类存档会在新回合或恢复执行进入模型、世界写入和账务步骤前被明确拒绝；即使任务尚未到期也一样。用户可以删除这个旧存档并新建游戏，无需构造迁移或零计量结算。读取不会自动删除待办或存档，当前 `single_npc_reply` 确定性交付及正常结算快照恢复不受影响。
